# Sharing dictionaries and settings across machines

Goal: one SKK input engine, same behaviour and same learned data on Windows (CorvusSKK), Linux (ibus-skk) and Vim/Neovim (skkeleton), with Android possible later. The problem this slice addresses is that every implementation keeps its user dictionary in its own path, format and encoding, and none of them merges concurrent edits.
Finding 1: the skkserv protocol has no write command, no SKK IME syncs a user dictionary to a cloud, and no timestamped or three-way merge tool was found.
Finding 2: the cheapest working scheme today is one canonical UTF-8 file plus a per-machine merge step and a tombstone list for deletions, but CorvusSKK cannot consume a UTF-8 user dictionary without conversion.
Finding 3: skkeleton no longer has a `userJisyo` option. It was renamed `userDictionary` on 2024-01-11 ([doc/skkeleton.jax](https://raw.githubusercontent.com/vim-skk/skkeleton/main/doc/skkeleton.jax)) [fetched].

## 1. Where each implementation keeps its data

**ddskk.** User dictionary is `skk-jisyo`, defaulting to `~/.skk-jisyo`, or `jisyo` under `skk-user-directory` when set, with backup `~/.skk-jisyo.BAK` ([skk-vars.el](https://raw.githubusercontent.com/skk-dev/ddskk/master/skk-vars.el)) [fetched]. It is SKK-JISYO text and the save path refuses to write a file missing `^;; okuri-ari entries.$` or `^;; okuri-nasi entries.$` ([skk.el](https://raw.githubusercontent.com/skk-dev/ddskk/master/skk.el)) [fetched]. Encoding comes from `skk-jisyo-code`, whose `nil` default means `euc-jis-2004`, and the individual dictionary can override it as a cons `(PATH . CODING-SYSTEM)` ([skk-vars.el](https://raw.githubusercontent.com/skk-dev/ddskk/master/skk-vars.el), [manual 6.10](https://ddskk.readthedocs.io/ja/latest/06_apps.html)) [fetched]. Autosave fires every `skk-jisyo-save-count` (default 50) updates ([skk-vars.el](https://raw.githubusercontent.com/skk-dev/ddskk/master/skk-vars.el)) [fetched]. The optional learning feature stores a separate S-expression file, `skk-study-file`, default `~/.skk-study`, with a `skk-study-file format version` header ([skk-vars.el](https://raw.githubusercontent.com/skk-dev/ddskk/master/skk-vars.el), [skk-study.el](https://raw.githubusercontent.com/skk-dev/ddskk/master/skk-study.el)) [fetched]. Maintenance: latest commit 2026-03-29, latest release DDSKK 17.2 on 2026-03-29 ([commits](https://github.com/skk-dev/ddskk/commits/master.atom), [releases](https://github.com/skk-dev/ddskk/releases.atom)) [fetched].

**skkeleton.** Option `userDictionary`, default `~/.skkeleton`, and "JavaScriptの制約によりエンコーディングはUTF-8限定になります" ([doc/skkeleton.jax](https://raw.githubusercontent.com/vim-skk/skkeleton/main/doc/skkeleton.jax)) [fetched]. `immediatelyDictionaryRW` defaults `v:true` and reads and writes the user dictionary on every conversion and commit ([same](https://raw.githubusercontent.com/vim-skk/skkeleton/main/doc/skkeleton.jax)) [fetched]. Global dictionaries take a path or `[path, encoding]` tuple, and JISYO JSON/YAML/msgpack files are supported alongside SKK text ([same](https://raw.githubusercontent.com/vim-skk/skkeleton/main/doc/skkeleton.jax)) [fetched]. It needs denops.vim and Deno 1.42.0 or newer ([README](https://raw.githubusercontent.com/vim-skk/skkeleton/main/README.md)) [fetched]. Maintenance: latest commit 2026-10-31, release 3.0.0 on 2026-09-11 ([commits](https://github.com/vim-skk/skkeleton/commits/main.atom), [releases](https://github.com/vim-skk/skkeleton/releases.atom)) [fetched].

**libskk.** Dictionary types are file dictionary, user dictionary, skkserv and CDB ([README](https://raw.githubusercontent.com/ueno/libskk/master/README.md)) [fetched]. `UserDict` loads the whole file into two maps, re-reads when the file ETag changes, and on save rewrites both sections sorted, emits a `;;; -*- coding: NAME -*-` header, and passes the cached ETag to `file.replace_contents` ([user-dict.vala](https://raw.githubusercontent.com/ueno/libskk/master/libskk/user-dict.vala)) [fetched]. The constructor defaults to UTF-8 but callers pass their own encoding ([user-dict.vala](https://raw.githubusercontent.com/ueno/libskk/master/libskk/user-dict.vala)) [fetched]. Maintenance: latest commit 2026-10-07, release libskk 1.1.1 on 2026-02-25 ([commits](https://github.com/ueno/libskk/commits/master.atom), [releases](https://github.com/ueno/libskk/releases.atom)) [fetched].

**ibus-skk (libskk frontend).** Default list is `$XDG_CONFIG_HOME/ibus-skk/user.dict` with `mode=readwrite`, `/usr/share/skk/SKK-JISYO.L` read only, and a server at `localhost:1178` ([preferences.vala](https://raw.githubusercontent.com/ueno/ibus-skk/master/src/preferences.vala)) [fetched]. Maintenance: cskk latest commit 2026-10-11, release v4.0.0 on 2026-09-19 ([commits](https://github.com/naokiri/cskk/commits/master.atom), [releases](https://github.com/naokiri/cskk/releases.atom)) [fetched]; fcitx5-cskk latest commit 2026-09-04, release v1.2.0 dated 2023-02-04 ([commits](https://github.com/fcitx/fcitx5-cskk/commits/master.atom), [releases](https://github.com/fcitx/fcitx5-cskk/releases.atom)) [fetched].

## 2. Existing merge tools

**skktools.** `skkdic-expr2` merges dictionaries as sets: `Usage: skkdic-expr2 [-d delimiter] [-o output] jisyo1 [[+-^] jisyo2]...`, where a bare name or `+` adds, `-` subtracts and `^` intersects ([skkdic-expr2.c](https://raw.githubusercontent.com/skk-dev/skktools/master/skkdic-expr2.c)) [fetched]. Its output order comes from a GTree with `strcmp`, that is byte order, and the source contains no encoding conversion ([same](https://raw.githubusercontent.com/skk-dev/skktools/master/skkdic-expr2.c)) [fetched]. `skkdic-sort` sorts lines with `qsort` over byte comparison, rewrites the two `;;` header lines, and drops comment lines ([skkdic-sort.c](https://raw.githubusercontent.com/skk-dev/skktools/master/skkdic-sort.c)) [fetched]. Neither tool knows about timestamps. Maintenance: latest commit 2026-04-02, release skktools 1.3.4 dated 2018-08-08 ([commits](https://github.com/skk-dev/skktools/commits/master.atom), [releases](https://github.com/skk-dev/skktools/releases.atom)) [fetched].

**meskkdic, the Windows counterpart.** It merges and diffs with the same `+`/`-` operators, requires inputs in one encoding, has a `-W` mode for UTF-16 (LE, BOM) input and UTF-16 CR+LF output, a `-O` mode that keeps okuri-ari bracket blocks and skips sorting, and joins differing annotations with commas ([meskkdic](https://github.com/nathancorvussolis/meskkdic)) [snippet]. This is the natural tool to convert between CorvusSKK's UTF-16 world and the others.

**ddskk has no merge feature.** I searched every `.el` file in the repository for "merge" and found none, and the manual's dictionary-tools section points readers to external C and Ruby tools ([manual 9.5](https://ddskk.readthedocs.io/ja/latest/09_info.html), [repository files](https://github.com/skk-dev/ddskk)) [fetched]. What ddskk does have is `skk-jisyo-edit-mode.el` for editing the user dictionary in place ([repository files](https://github.com/skk-dev/ddskk)) [fetched].

**yaskkserv2's builder merges dictionaries.** `yaskkserv2_make_dictionary` merges several SKK dictionaries into one server dictionary at build time ([README](https://raw.githubusercontent.com/wachikun/yaskkserv2/master/README.md)) [fetched]. That is a union done once, not a repeated merge.

**Three-way or timestamped merge.** I found none. Every published recipe I read is a set union, sometimes minus a delete list, run by hand or by cron (sections 3 and 4).

## 3. Existing sync approaches

**Shared file over online storage.** The CorvusSKK author's own procedure moves `%AppData%\CorvusSKK` into an online-storage folder and links it back with `mklink /d` or `mklink /j`, after `taskkill /im imcrvmgr.exe` ([blog post](https://nathancorvussolis.blogspot.com/2016/07/onlinestorage-corvusskk.html)) [fetched]. His warning is direct: "複数のPCやユーザーで、ローカルおよびリモートの同じディレクトリを使ってしまうとお互いに上書きしあってしまいます" ([same](https://nathancorvussolis.blogspot.com/2016/07/onlinestorage-corvusskk.html)) [fetched].

**SKKSync, a Windows reload helper.** It replaces the SKKFEP dictionary process with one that reloads the user dictionary file after 3 seconds without further updates, and shortens autosave from 3 minutes to 3 seconds, explicitly to avoid reading a half-written file ([SKKSync](http://coexe.web.fc2.com/skksync.html)) [snippet]. This is the closest existing answer to "one shared file, many machines" on Windows.

**Per-host files plus a cron merge.** One long-running report keeps one dictionary per hostname under Dropbox, merges each day with `skkdic-expr2`, and keeps a manual delete-list dictionary because otherwise "他のマシンで削除した単語が、次回同期で復活する" ([blog](https://ponkotuy.hatenadiary.org/entry/20110219/1298069268)) [snippet]. The same post notes Dropbox conflicts and converts SKKIME's UTF-16 dictionaries with `iconv` ([same](https://ponkotuy.hatenadiary.org/entry/20110219/1298069268)) [snippet]. Another report is the plain manual loop `skkdic-expr2 skk-jisyo1 + skk-jisyo2 + skk-jisyo3 | skkdic-sort > skk-new-jisyo` run about monthly ([blog](https://yourpalm.jubenoum.com/entry/archives/490/)) [snippet].

**skkserv over the network is read only.** The protocol as documented has five commands: `0` disconnect, `1` look up a midashi, `4` complete a midashi prefix, `2` version, `3` host list ([README, SKK protocol memo](https://raw.githubusercontent.com/wachikun/yaskkserv2/master/README.md)) [fetched]. There is no register or delete command, and the transport encoding is EUC, not the dictionary encoding ([same](https://raw.githubusercontent.com/wachikun/yaskkserv2/master/README.md)) [fetched]. Clients treat the server as a search source only, and macSKK states plainly that it is not a server ([辞書](https://mtgto.github.io/macSKK/config/dictionary)) [fetched]. No SKK server that accepts learning from clients was found.

**yaskkserv2.** It converts SKK dictionaries into its own architecture-dependent dictionary, merges multiple dictionaries during that conversion, answers `1` and `4`, and dropped dictionary reload in favour of a restart ([README](https://raw.githubusercontent.com/wachikun/yaskkserv2/master/README.md)) [fetched]. It also notes that its Google cache file is not locked, so several instances must use different cache files ([same](https://raw.githubusercontent.com/wachikun/yaskkserv2/master/README.md)) [fetched]. Maintenance: latest commit 2026-10-03, release dated 2023-09-15 ([commits](https://github.com/wachikun/yaskkserv2/commits/master.atom), [releases](https://github.com/wachikun/yaskkserv2/releases.atom)) [fetched].

**Servers backed by Google's IME.** yaskkserv2 calls the Google Japanese Input API by default when its own dictionary misses, with `--google-japanese-input=notfound|disable|last|first` ([README](https://raw.githubusercontent.com/wachikun/yaskkserv2/master/README.md)) [fetched]. ddskk can call the Google CGI API as a search program via `skk-search-web` ([manual 6.13.4](https://ddskk.readthedocs.io/ja/latest/06_apps.html)) [fetched], and skkeleton has a `google_japanese_input` source, without completion support ([doc/skkeleton.jax](https://raw.githubusercontent.com/vim-skk/skkeleton/main/doc/skkeleton.jax)) [fetched].

**Cloud sync inside an IME.** macSKK syncs settings between Macs through iCloud key-value storage, and lists dictionaries, the kana-rule selection, keyboard layout, server address and private mode as deliberately not synced ([iCloud](https://mtgto.github.io/macSKK/config/icloud)) [fetched]. Its README keeps "iCloudにマイ辞書を保存して他環境と共有できるようにする" as an unimplemented item ([README](https://raw.githubusercontent.com/mtgto/macSKK/main/README.md)) [fetched]. No other IME here syncs a user dictionary to a cloud.

## 4. Failure modes the sources report

**Whole-file rewrite versus concurrent edits.** ddskk keeps the dictionary in a buffer and rewrites the file, and its only concurrency handling is opt-in: `skk-share-private-jisyo` makes it "「複数の SKK プロセスが特定の個人辞書を共有している」を考慮した上で処理を行う" ([skk-vars.el](https://raw.githubusercontent.com/skk-dev/ddskk/master/skk-vars.el)) [fetched]. Even then the update is "delete the buffer contents, re-read the file, then replay this instance's pending updates" ([skk-update-shared-jisyo](https://raw.githubusercontent.com/skk-dev/ddskk/master/skk.el)) [fetched], which is a replay, not a merge. ddskk also refuses to save a file that became empty or smaller than the old one without confirmation ([skk-check-size-and-do-save-jisyo](https://raw.githubusercontent.com/skk-dev/ddskk/master/skk.el)) [fetched].

**Whole-file rewrite elsewhere.** libskk rewrites both sections on save ([user-dict.vala](https://raw.githubusercontent.com/ueno/libskk/master/libskk/user-dict.vala)) [fetched] and passes the cached ETag to `replace_contents`; a stale ETag is documented by GLib to raise an error rather than to overwrite, so libskk fails the save instead of merging (inference from the API used, not tested here). cskk renames the old file to `.BAK` and writes a fresh one ([user_dictionary.rs](https://raw.githubusercontent.com/naokiri/cskk/master/cskk/src/dictionary/user_dictionary.rs)) [fetched], so a second process's writes are simply replaced. CorvusSKK keeps the dictionary in memory in `imcrvmgr.exe` and overwrites the file on IME off, focus loss, sleep resume, and process exit ([README](https://raw.githubusercontent.com/nathancorvussolis/corvusskk/master/README.md)) [fetched]. skkeleton writes the user dictionary on every commit when `immediatelyDictionaryRW` is true ([doc/skkeleton.jax](https://raw.githubusercontent.com/vim-skk/skkeleton/main/doc/skeleton.jax)) [fetched], which widens the window for interleaving.

**Editing while the process holds the dictionary.** CorvusSKK's README tells users to terminate `imcrvmgr.exe` before editing `userdict.txt` directly ([README](https://raw.githubusercontent.com/nathancorvussolis/corvusskk/master/README.md)) [fetched]. macSKK warns that force quit loses unsaved changes ([辞書](https://mtgto.github.io/macSKK/config/dictionary)) [fetched], and that two differently signed builds touching the same user dictionary trigger a sandbox permission prompt that can lock the release build out ([README](https://raw.githubusercontent.com/mtgto/macSKK/main/README.md)) [fetched]. SKKSync's 3-second settle exists precisely because a reader can catch a half-written file ([SKKSync](http://coexe.web.fc2.com/skksync.html)) [snippet].

**Network shares and file locking on Windows.** CorvusSKK notes that if the user dictionary backup directory is a Windows network share, saving at logoff, shutdown or restart may fail ([README](https://raw.githubusercontent.com/nathancorvussolis/corvusskk/master/README.md)) [fetched]. SKKSync's changelog adds a Win32 detail: file-change notification cannot report completion, so a write in progress is indistinguishable from a finished one, which is why the fixed wait is used ([SKKSync](http://coexe.web.fc2.com/skksync.html)) [snippet].

**Encoding mismatch.** Defaults differ across the three machines the owner uses: ddskk writes `euc-jis-2004` ([skk-vars.el](https://raw.githubusercontent.com/skk-dev/ddskk/master/skk-vars.el)) [fetched], ibus-skk and fcitx5-skk default to `EUC-JP` ([preferences.vala](https://raw.githubusercontent.com/ueno/ibus-skk/master/src/preferences.vala), [skk.cpp](https://raw.githubusercontent.com/fcitx/fcitx5-skk/master/src/skk.cpp)) [fetched], skkeleton is UTF-8 only ([doc/skkeleton.jax](https://raw.githubusercontent.com/vim-skk/skkeleton/main/doc/skeleton.jax)) [fetched], macSKK prefers a `.utf8` file name ([辞書](https://mtgto.github.io/macSKK/config/dictionary)) [fetched], and CorvusSKK writes UTF-16LE with BOM ([README](https://raw.githubusercontent.com/nathancorvussolis/corvusskk/master/README.md)) [fetched]. libskk's own constructor defaults to UTF-8 while its frontends pass EUC-JP ([user-dict.vala](https://raw.githubusercontent.com/ueno/libskk/master/libskk/user-dict.vala), [engine.vala](https://raw.githubusercontent.com/ueno/ibus-skk/master/src/engine.vala)) [fetched], so the same path read by two different frontends can be decoded differently. A BOM left in a UTF-8 dictionary is another hazard, since the tools compare bytes: `skkdic-expr2` and `skkdic-sort` do no conversion at all ([skkdic-expr2.c](https://raw.githubusercontent.com/skk-dev/skktools/master/skkdic-expr2.c), [skkdic-sort.c](https://raw.githubusercontent.com/skk-dev/skktools/master/skkdic-sort.c)) [fetched]. SKKepsis users are told to rewrite the `coding:` header line when converting, because "ファイルに記載された文字コードと実際の文字コードが一致しなくなってしまう" ([SKKepsis](https://www.chinpui.org/hack/softwares/skkepsis/)) [fetched].

**Line endings.** CorvusSKK's KanaTable accepts CR+LF or LF ([README](https://raw.githubusercontent.com/nathancorvussolis/corvusskk/master/README.md)) [fetched], meskkdic's `-W` mode emits CR+LF ([meskkdic](https://github.com/nathancorvussolis/meskkdic)) [snippet], and macSKK's rule files are specified as "UTF-8 + LF (BOMなし)" ([ローマ字かな変換ルール](https://mtgto.github.io/macSKK/config/kana-rule)) [fetched]. I found no source describing what happens when a `.skk-jisyo` gains CRLF line endings.

**Sorted order is not preserved by hand edits.** ddskk has `skk-jisyo-fix-order` to keep candidate order stable when appending ([skk-vars.el](https://raw.githubusercontent.com/skk-dev/ddskk/master/skk-vars.el)) [fetched], while skkdic-sort, libskk and cskk each impose their own order ([skkdic-sort.c](https://raw.githubusercontent.com/skk-dev/skktools/master/skkdic-sort.c), [user-dict.vala](https://raw.githubusercontent.com/ueno/libskk/master/libskk/user-dict.vala), [user_dictionary.rs](https://raw.githubusercontent.com/naokiri/cskk/master/cskk/src/dictionary/user_dictionary.rs)) [fetched]. A round trip through a merge tool therefore reorders candidates on every machine.

**Deleted entries come back.** A union cannot express deletion, which is why one report keeps a separate delete-list dictionary and subtracts it ([blog](https://ponkotuy.hatenadiary.org/entry/20110219/1298069268)) [snippet]. CorvusSKK's answer is different and local: private mode skips user-dictionary updates entirely ([README](https://raw.githubusercontent.com/nathancorvussolis/corvusskk/master/README.md)) [fetched].

## 5. Design options for one shared user dictionary

### (a) Sync one canonical file

Evidence that it works at all: macSKK re-reads the user dictionary when another process changes it ([辞書](https://mtgto.github.io/macSKK/config/dictionary)) [fetched], ddskk can replay its own pending updates over a file another Emacs wrote ([skk-update-shared-jisyo](https://raw.githubusercontent.com/skk-dev/ddskk/master/skk.el)) [fetched], and SKKSync automates reload on Windows ([SKKSync](http://coexe.web.fc2.com/skksync.html)) [snippet].

What each implementation would need:

- CorvusSKK is the blocker. Its user dictionary must be UTF-16LE with BOM ([README](https://raw.githubusercontent.com/nathancorvussolis/corvusskk/master/README.md)) [fetched], so a canonical UTF-8 file has to be converted on the way in and out, or the canonical file has to stay UTF-16 and everything else converts. meskkdic's `-W` mode already does merge and conversion in one step ([meskkdic](https://github.com/nathancorvussolis/meskkdic)) [snippet].
- skkeleton needs nothing but a UTF-8 file at `userDictionary`; it cannot read EUC-JP user data at all ([doc/skkeleton.jax](https://raw.githubusercontent.com/vim-skk/skeleton/main/doc/skeleton.jax)) [fetched]. Correction, the source is [skkeleton.jax](https://raw.githubusercontent.com/vim-skk/skkeleton/main/doc/skkeleton.jax) [fetched].
- ibus-skk and fcitx5-skk need their dictionary plist encoding changed from the `EUC-JP` default ([preferences.vala](https://raw.githubusercontent.com/ueno/ibus-skk/master/src/preferences.vala), [skk.cpp](https://raw.githubusercontent.com/fcitx/fcitx5-skk/master/src/skk.cpp)) [fetched].
- Every implementation writes the whole file from memory, so the scheme needs a discipline of one active writer per machine plus a merge step between machines. The existing merge step is `skkdic-expr2` plus `skkdic-sort` ([skkdic-expr2.c](https://raw.githubusercontent.com/skk-dev/skktools/master/skkdic-expr2.c)) [fetched], and it cannot express deletion, so a tombstone file subtracted with `-` is needed ([blog](https://ponkotuy.hatenadiary.org/entry/20110219/1298069268)) [snippet].
- Order churn is unavoidable because each writer re-sorts ([user-dict.vala](https://raw.githubusercontent.com/ueno/libskk/master/libskk/user-dict.vala)) [fetched], which makes git diffs and conflict resolution noisy.

### (b) An append-only log of learning events, merged per machine

No implementation does this today. The nearest primitives are ddskk's `skk-jisyo-update-vector` of pending operations, which is already an operation list that is replayed rather than merged ([skk.el](https://raw.githubusercontent.com/skk-dev/ddskk/master/skk.el)) [fetched], ddskk's separate learning file with its own format version and a "Broken skk-study-file" error ([skk-study.el](https://raw.githubusercontent.com/skk-dev/ddskk/master/skk-study.el)) [fetched], CorvusSKK's timestamped backups ([README](https://raw.githubusercontent.com/nathancorvussolis/corvusskk/master/README.md)) [fetched], and AndroidSKK's jdbm `*.lg` companion file ([SKKDicManager.kt](https://raw.githubusercontent.com/deadend-noname/AndroidSKK/main/java/jp/deadend/noname/skk/SKKDicManager.kt)) [fetched]. None of them is mergeable by another machine.

What each implementation would need: an event record carrying midashi, candidate, okuri-ari flag, timestamp and machine id, plus a per-machine log file and a merge that is a set union over events with a last-writer rule per (midashi, candidate). ddskk would have to persist its update vector instead of replaying it into the file, skkeleton would have to write a log instead of the whole dictionary on every commit ([doc/skkeleton.jax](https://raw.githubusercontent.com/vim-skk/skkeleton/main/doc/skkeleton.jax)) [fetched], libskk and cskk would need the same change in `save`, and CorvusSKK would need a hook inside `imcrvmgr.exe`. This option carries no shared-file encoding problem, since each machine writes its own log and the merged text file is regenerated, but no existing client can produce the log.

### (c) A personal server with a small write protocol

Evidence against the current protocol: the server commands are the five read and metadata ones ([README](https://raw.githubusercontent.com/wachikun/yaskkserv2/master/README.md)) [fetched], clients only ever attach a file dictionary as writable ([engine.vala](https://raw.githubusercontent.com/ueno/ibus-skk/master/src/engine.vala), [skk.cpp](https://raw.githubusercontent.com/fcitx/fcitx5-skk/master/src/skk.cpp)) [fetched], and yaskkserv2 rebuilt its dictionary at startup with no reload ([README](https://raw.githubusercontent.com/wachikun/yaskkserv2/master/README.md)) [fetched].

What each implementation would need: new commands beyond `0/1/4/2/3`, and a patch in every client: ddskk's `skk-server.el` ([repository files](https://github.com/skk-dev/ddskk)) [fetched], libskk's `skkserv.vala` ([repository files](https://github.com/ueno/libskk)) [fetched], skkeleton's `skk_server` source ([doc/skkeleton.jax](https://raw.githubusercontent.com/vim-skk/skkeleton/main/doc/skkeleton.jax)) [fetched], macSKK ([辞書](https://mtgto.github.io/macSKK/config/dictionary)) [fetched], and CorvusSKK ([README](https://raw.githubusercontent.com/nathancorvussolis/corvusskk/master/README.md)) [fetched]. The server side is the easy part; the client fleet is the cost. Note also that the transport encoding is fixed at EUC by protocol convention ([README](https://raw.githubusercontent.com/wachikun/yaskkserv2/master/README.md)) [fetched], so a write protocol carrying UTF-8 text would need an escape or a new command set.

**Reading of the three.** For a new engine the owner writes, (b) is the only option that needs no cooperation from existing clients, because the new engine owns both the log and the merge. For the current three machines today, (a) with a merged text file and a tombstone list is the only path that uses existing tools, and its cost is the CorvusSKK conversion step plus a single-writer rule. (c) buys nothing until at least one client is patched.

## 6. Settings worth sharing, and how each implementation expresses them

**Romaji table.** ddskk compiles `skk-rom-kana-base-rule-list` and `skk-rom-kana-rule-list` into a rule tree at startup ([skk.el](https://raw.githubusercontent.com/skk-dev/ddskk/master/skk.el), [skk-vars.el](https://raw.githubusercontent.com/skk-dev/ddskk/master/skk-vars.el)) [fetched]. skkeleton selects `kanaTable` (default `rom`), extends it with `skkeleton#register_kanatable`, and can load rule files such as `azik_us.rule` through `globalKanaTableFiles` ([doc/skkeleton.jax](https://raw.githubusercontent.com/vim-skk/skkeleton/main/doc/skkeleton.jax)) [fetched]. libskk supports romaji-to-kana, AZIK, TUT-Code and NICOLA rules ([README](https://raw.githubusercontent.com/ueno/libskk/master/README.md)) [fetched], selected by name in the frontend plist, where ibus-skk defaults `typing_rule` to `default` ([preferences.vala](https://raw.githubusercontent.com/ueno/ibus-skk/master/src/preferences.vala)) [fetched]. macSKK uses `kana-rule*.conf` files in its Settings folder, comma separated with up to five fields, UTF-8 and LF, with `#!use-default` inheritance ([ローマ字かな変換ルール](https://mtgto.github.io/macSKK/config/kana-rule)) [fetched]. CorvusSKK keeps the table in `config.xml` and can import and export a KanaTable file, tab separated, UTF-16LE or UTF-8 ([README](https://raw.githubusercontent.com/nathancorvussolis/corvusskk/master/README.md)) [fetched].

**Key bindings.** These are the least portable part. ddskk defines them as Emacs keymaps in Lisp ([skk.el](https://raw.githubusercontent.com/skk-dev/ddskk/master/skk.el)) [fetched]. skkeleton uses `skkeleton#register_keymap` plus the `g:skkeleton#mapped_keys` list ([doc/skkeleton.jax](https://raw.githubusercontent.com/vim-skk/skkeleton/main/doc/skkeleton.jax)) [fetched]. libskk documents keymap and romaji table customization separately ([README](https://raw.githubusercontent.com/ueno/libskk/master/README.md)) [fetched]. macSKK has named key-binding sets that can be copied, renamed and edited, and it syncs the set through iCloud as its own category ([キーバインド](https://mtgto.github.io/macSKK/config/keybinding), [iCloud](https://mtgto.github.io/macSKK/config/icloud)) [fetched]. CorvusSKK stores key settings as ECMAScript regular expressions plus virtual key codes in `config.xml` ([README](https://raw.githubusercontent.com/nathancorvussolis/corvusskk/master/README.md)) [fetched]. Only macSKK has an existing mechanism for shipping a key-binding set between machines.

**Dictionary list and search order.** ddskk uses `skk-extra-jisyo-file-list`, where an entry is a path or a `(path . coding-system)` pair ([skk-vars.el](https://raw.githubusercontent.com/skk-dev/ddskk/master/skk-vars.el), [manual 6.10](https://ddskk.readthedocs.io/ja/latest/06_apps.html)) [fetched]. skkeleton uses `globalDictionaries` with the same path or `[path, encoding]` shape ([doc/skkeleton.jax](https://raw.githubusercontent.com/vim-skk/skkeleton/main/doc/skkeleton.jax)) [fetched]. ibus-skk and fcitx5-skk use the same `type=file,file=...,mode=...,encoding=...` plist format ([engine.vala](https://raw.githubusercontent.com/ueno/ibus-skk/master/src/engine.vala), [dictionary_list.in](https://raw.githubusercontent.com/fcitx/fcitx5-skk/master/src/dictionary_list.in)) [fetched], which is good news: one generator could emit the list for both. macSKK discovers files in its Dictionaries folder and lets the user toggle and order them ([辞書](https://mtgto.github.io/macSKK/config/dictionary)) [fetched]. CorvusSKK has one imported dictionary file plus an optional single server ([README](https://raw.githubusercontent.com/nathancorvussolis/corvusskk/master/README.md)) [fetched].

**What actually benefits from sharing.** The romaji table and the dictionary list are data files and can be generated once for all three machines, with the fcitx5-skk plist covering ibus-skk too. Key bindings are the one item where each implementation's expression is genuinely different, and macSKK's key-binding set is the only model that treats a binding set as a named, transferable object ([キーバインド](https://mtgto.github.io/macSKK/config/keybinding)) [fetched].
